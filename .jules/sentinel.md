## 2024-05-24 - [CRITICAL] Timing Attack Vulnerability in Admin Auth
**Vulnerability:** A timing attack vulnerability was identified in `src/app/actions/admin.ts`. The strict equality operator (`===`) was used for comparing the admin password and validating the session cookie. This allows an attacker to deduce the contents of a secret string (e.g., password or session token) by precisely measuring the time it takes for the application to reject an incorrect string. The comparison exits early as soon as a mismatch is found, revealing the length of the matching prefix.
**Learning:** Using standard string equality operators for sensitive comparisons like passwords and tokens exposes them to timing side-channel attacks. A cryptographic constant-time comparison must be used, even in simple login scenarios.
**Prevention:** Always use `crypto.timingSafeEqual()` (or an equivalent constant-time comparison library function) when comparing sensitive secrets such as passwords, API keys, or session tokens. To use `crypto.timingSafeEqual()`, both inputs must have the same length, which is why they are hashed first in `secureCompare`. Furthermore, we made the session salt an environment variable to prevent salt reuse and exposure in the source code.
